**InsurAI** is a production-grade, full-stack AI platform designed to demystify complex health insurance contracts. By combining document parsing, multi-pass Large Language Model (LLM) extraction, isolated semantic vector search, and a deterministic cost calculation engine, InsurAI empowers policyholders and advisors to understand their coverage, uncover hidden exclusions, estimate out-of-pocket hospital bills, and converse with a citation-backed AI assistant.

## 💡 Overview & Problem Statement

Health insurance policies are notoriously dense, laden with legal jargon, and difficult for policyholders to decipher. Critical details—such as room-rent sub-limits, proportional co-payment penalties, pre-existing disease waiting periods, and day-care treatment exclusions—are often buried across dozens of pages. 

**InsurAI solves this by offering:**
1. **Instant Clarity**: Upload any policy PDF and obtain a verified breakdown of key clauses in seconds.
2. **Actionable Estimates**: Know estimated out-of-pocket hospitalization expenses before stepping into a hospital.
3. **Truth & Traceability**: Every answer generated by the assistant is grounded in the policy text with exact physical page citations.
4. **Conversational Persistence**: Continuous, multi-session chat history stored in MongoDB, accessible across devices just like on ChatGPT or Claude.

---

## ✨ Key Features

### 1. Policy Document Ingestion & Fact Extraction
- **Multi-Engine PDF Ingestion**: Extracts digital text using PyMuPDF (`fitz`) with automatic fallback to Tesseract OCR for scanned or rasterized policy documents.
- **Page-Bounded Chunking**: Partitions text into semantic chunks with overlap while preserving physical page boundaries and section headers.
- **3-Pass LLM Extraction**: Extracts structured attributes into a normalized schema:
  - *Sum Insured* (Base sum, restoration benefits)
  - *Room Rent Limits* (Daily allowance caps, ICU limits, proportionate deduction clauses)
  - *Co-payments & Deductibles* (Zone-based, tier-based, or age-based percentage co-pays)
  - *Waiting Periods* (Initial 30 days, specific ailments, pre-existing conditions)
  - *Exclusions & Conditions* (Non-medical consumables, cosmetic limits, OPD conditions)
- **Heuristic Fallback Engine**: If the LLM service is temporarily unreachable, deterministic regex heuristics extract core numerical limits to prevent processing failures.

### 2. Citation-Backed AI Chat & Persistent History
- **Modern AI Platform Experience**:
  - **MongoDB Persistence**: Conversations are saved to MongoDB (`db.conversations`) in real time.
  - **Date Grouping**: Chats in the sidebar are automatically categorized into **Today**, **Yesterday**, **Previous 7 Days**, and **Older**.
  - **Auto-Titling**: Conversations are automatically titled based on the intent of the initial prompt.
  - **Session Management**: Rename session titles inline, delete past chats, or search through previous discussions with keyword filtering.
  - **Mobile History Drawer**: Dedicated slide-over drawer providing mobile users with full history access.
- **Real-Time Streaming**: High-speed, token-by-token response streaming via WebSocket (`/api/chat/ws`) with automatic REST fallback (`/api/chat/message`).
- **Grounded Citations**: Every claim cites its exact source (e.g., `p. 4 · Section 3.1 - Room Rent Limits`) with excerpt verification.
- **Calibrated Confidence**: Displays real-time confidence scores (`high`, `medium`, `low`) and verification status badges.
- **Plain-Language Toggle**: Switch between formal insurance terminology and simplified, jargon-free explanations with one click.

### 3. Treatment Cost Estimator & What-If Simulations
- **Deterministic Math Engine**: Calculates out-of-pocket liabilities for medical procedures without LLM hallucinations.
- **Hospital Tiering & Rule Enforcement**:
  - Calculates applied room rent vs. allowed policy daily caps.
  - Computes proportional deduction penalties if an upgraded room is selected.
  - Deducts applicable policy deductibles and percentage co-pays.
  - Quantifies non-payable hospital expenses (gloves, PPE, administrative fees).
- **Interactive "What-If" Scenario Simulator**:
  - Adjust room rent, length of stay, or hospital tier in real time.
  - Simulates liability changes dynamically while keeping the original baseline estimate intact.

### 4. Multi-Policy Comparison Engine
- **Side-by-Side Analysis**: Compare 2 or more health insurance policies across standardized parameters:
  - Sum insured flexibility & cumulative bonus multiplier
  - Room rent caps (no cap vs. 1% daily limit)
  - Pre-existing disease (PED) waiting periods (12 to 48 months)
  - Day-care procedure coverage
- **Coverage Gap & Red-Flag Warnings**: Highlights hidden restrictions, high copayments, and sub-limits that could lead to claim rejection.

### 5. Zero-Hallucination & Verification Architecture
- **Tenant & Policy Isolation**: Every uploaded document receives a dedicated ChromaDB collection (`policy_{policy_id}`), preventing cross-policy retrieval contamination.
- **Dual Query Routing**:
  - *Structured Route*: Fast, direct lookup from pre-extracted MongoDB facts for standard questions (e.g., "What is my room rent cap?").
  - *Semantic Route*: Cosine similarity retrieval over ChromaDB chunks for nuanced, circumstantial inquiries.
- **Self-Verification Pipeline**: Before returning an answer, the RAG engine performs quote checking against retrieved chunks. If an answer cannot be substantiated, it is flagged as unsupported.

### 6. Modern Responsive Dark-Themed UI
- **Rich Aesthetics**: Custom dark palette (`#07070d`) with ambient nebula lighting, starfield canvas effects, and glassmorphic cards.
- **Bento-Grid Dashboard**: Overview of uploaded policies, extracted fact summaries, quick actions, and recent activity.
- **Collapsible Navigation**: 3-line minimization button collapses the sidebar into an icon-only strip with centered navigation items.
- **Responsive Layout**: Designed for seamless usability across desktops, tablets, and smartphones.

## 🚀 General Instructions on How to Run

Follow these step-by-step instructions to get InsurAI running locally.

### 1. Clone Repository

```bash
git clone https://github.com/somanirohan/InsureAI.git
cd InsureAI
```

---

### 2. Environment Configuration

Create a `.env` file in the root directory (or edit the existing `.env` file):

```env
# ── Server & Security ──────────────────────────────────────────────
PORT=5001
ENVIRONMENT=development
JWT_SECRET=insureai_super_secret_jwt_key_2026_secure_key
JWT_EXPIRES_IN=7d
CLIENT_URL=http://localhost:5173
ALLOWED_ORIGINS=http://localhost:5173,http://127.0.0.1:5173
UPLOAD_DIR=server/uploads

# ── MongoDB Database ───────────────────────────────────────────────
MONGO_URI=mongodb://127.0.0.1:27017/insurai
MONGO_DB_NAME=insurai

# ── LLM Provider (Options: ollama | openrouter | nvidia) ───────────
LLM_PROVIDER=ollama
OLLAMA_BASE_URL=http://localhost:11434
OLLAMA_MODEL=mistral:7b

# (Optional: If using OpenRouter or NVIDIA NIM)
OPENROUTER_API_KEY=
OPENROUTER_MODEL=meta-llama/llama-3-8b-instruct
NVIDIA_API_KEY=

# ── Embedding Provider (Options: ollama | api) ────────────────────
EMBEDDING_PROVIDER=ollama
OLLAMA_EMBEDDING_MODEL=nomic-embed-text
CHROMA_PERSIST_DIR=./chroma_store

# ── Chunking & Retrieval Parameters ────────────────────────────────
CHUNK_SIZE=500
CHUNK_OVERLAP=80
TOP_K=5
OCR_TEXT_THRESHOLD=50
```

---

### 3. Backend Setup

Ensure you have **Python 3.11** installed.

```bash
# 1. Create a Python virtual environment
python -m venv venv

# 2. Activate the virtual environment
# Windows (PowerShell):
.\venv\Scripts\Activate.ps1
# Windows (cmd):
.\venv\Scripts\activate.bat
# Linux / macOS:
source venv/bin/activate

# 3. Upgrade pip and install dependencies
pip install --upgrade pip
pip install -r requirements.txt
```

---

### 4. Frontend Setup

Ensure you have **Node.js 18+** installed.

```bash
cd client
npm install
cd ..
```

---

### 5. Local LLM & Embedding Setup (Ollama)

If you are using local inference via [Ollama](https://ollama.com/):

```bash
# 1. Start the Ollama daemon
ollama serve

# 2. Pull the required models (in a separate terminal)
ollama pull mistral:7b
ollama pull nomic-embed-text
```

> **Note**: InsurAI includes built-in heuristic fallbacks and ChromaDB native embeddings. If Ollama is not installed or running, the core application will still function using deterministic heuristic extraction.

---

### 6. Database Seeding

InsurAI includes a seeder script that provisions a ready-to-use demo account, sample processed policies with facts, pre-computed vector embeddings, and an initial chat session:

```bash
python server/utils/seeder.py
```

**Default Demo Credentials:**
- **Email:** `demo@insurai.com`
- **Password:** `password123`

---

### 7. Running the Application

#### Option A: One-Command Startup (Recommended)

Run the included startup script (Bash / Git Bash / macOS / Linux):

```bash
chmod +x run.sh
./run.sh
```

This verifies MongoDB and Ollama connectivity and launches both the backend and frontend concurrently.

#### Option B: Running in Separate Terminals

**Terminal 1 — FastAPI Backend:**
```bash
# Make sure your virtual environment is active
python server/main.py
```
*Backend runs on `http://localhost:5001`*

**Terminal 2 — React Frontend:**
```bash
cd client
npm run dev
```
*Frontend runs on `http://localhost:5173`*

#### Access Points:
- **Web Application:** [http://localhost:5173](http://localhost:5173)
- **Interactive API Documentation (Swagger UI):** [http://localhost:5001/docs](http://localhost:5001/docs)
- **Alternative API Docs (ReDoc):** [http://localhost:5001/redoc](http://localhost:5001/redoc)
- **Health Check Endpoint:** [http://localhost:5001/api/health](http://localhost:5001/api/health)

---

### 8. Running the Automated Test Suites

The test suite covers unit logic, vector store isolation, database schemas, and chat persistence:

```bash
# Run all fast unit tests (mocked DB & RAG, runs in ~3s):
python -m pytest server/tests/test_unit_rag_adapter.py \
                 server/tests/test_unit_fact_mapper.py \
                 server/tests/test_unit_cost.py \
                 server/tests/test_unit_object_id_and_db.py \
                 server/tests/test_unit_chat_conversations.py \
                 server/tests/test_unit_processing_failure.py -v

# Run the complete end-to-end integration lifecycle test (requires MongoDB and Ollama):
python -m pytest server/tests/test_integration_flow.py -v
```

## ⚙️ Minimum System Requirements

The minimum and recommended specifications to run InsurAI smoothly:

### Hardware Requirements

| Component | Minimum Specification (API / Cloud Mode) | Recommended Specification (Local Ollama LLM) |
|---|---|---|
| **Processor (CPU)** | Dual-Core Intel Core i3 / AMD Ryzen 3 (2.0 GHz+) | 8-Core Intel Core i7 / AMD Ryzen 7 / Apple Silicon (M1/M2/M3) |
| **System Memory (RAM)** | 8 GB RAM | 16 GB RAM or higher (32 GB for concurrent 7B/8B models) |
| **Storage (Disk Space)**| 5 GB available SSD storage | 20 GB available NVMe SSD storage (to store model weights) |
| **Graphics (GPU)** | Not required (Integrated GPU sufficient) | Dedicated NVIDIA GPU with 6 GB+ VRAM (CUDA support) or Apple Silicon Unified Memory |
| **Network** | Broadband internet connection | Broadband internet (required for initial model download) |

### Software & Runtime Requirements

| Dependency | Minimum Supported Version | Recommended Version |
|---|---|---|
| **Operating System** | Windows 10 (64-bit), macOS 12 (Monterey), Ubuntu 20.04 LTS | Windows 11, macOS 14 (Sonoma), Ubuntu 22.04 LTS |
| **Python** | Python `3.11.0` | Python `3.11.x` |
| **Node.js** | Node.js `18.16.0` LTS | Node.js `20.x` LTS |
| **Package Manager** | `npm 9.x` or `yarn 1.22+` | `npm 10.x` |
| **MongoDB** | MongoDB Community Server `6.0` or MongoDB Atlas | MongoDB `7.0+` or MongoDB Atlas Cluster |
| **Ollama** *(Optional)* | Ollama `0.1.30` | Latest Ollama version |
| **Tesseract OCR** *(Optional)* | Tesseract `5.0+` (optional fallback for scanned PDFs) | Tesseract `5.3+` |
| **Web Browser** | Chrome 100+, Edge 100+, Firefox 100+, Safari 15+ | Latest Google Chrome or Brave |
